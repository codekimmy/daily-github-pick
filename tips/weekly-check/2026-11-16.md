## 아카이브에 넣을 만한 연출·도구

### 1. 코드 변신 — 코드 한 조각이 다른 조각으로 바뀌며 낱말(토큰)이 제자리를 찾아 미끄러짐
- **무엇이 나아지나**: 지금은 명령어 도구를 '터미널 타이핑'으로만 보여 줍니다. 파이썬에서 불러 쓰는 라이브러리(예: markitdown, wordcloud, noisereduce, zxcvbn)는 "옵션 한 줄을 더하면 결과가 이렇게 달라진다"가 핵심인데, 타이핑은 새로 치는 장면만 보여 줘서 **무엇이 바뀌었는지**가 잘 안 보입니다. 코드 변신은 바뀌지 않은 부분은 그대로 두고, 빠지는 낱말은 흐려지고 새 낱말은 나타나며, 자리를 옮기는 낱말은 미끄러져 이동하므로 **바뀐 곳만 눈에 들어옵니다.** 오른쪽(또는 아래)에 결과 그림을 함께 바꾸면 '코드 차이 → 결과 차이'가 한 장면에 담깁니다
- **어울리는 오픈소스**: 파이썬·자바스크립트 라이브러리, 설정 파일(YAML·TOML)로 동작이 바뀌는 도구, 명령어 옵션 비교(`--옵션` 하나 추가 전·후)
- **도입 방법**: 그날 `demo/render/page.html`에서 직접 구현합니다
  1. 전·후 코드를 낱말 단위로 나누고 색을 정합니다(코드 색칠은 npm `shiki` 4.6.0, MIT — 미리 색을 칠해 JSON으로 저장하면 렌더 때 따로 부를 필요 없음)
  2. 전·후에서 같은 낱말을 짝지어(최장 공통 부분열) 짝이 있는 낱말은 위치를 보간, 짝이 없는 낱말은 0.4~0.6초 흐려지기/나타나기
  3. GUIDE 5장 규칙대로 바뀐 뒤 2.5초 이상 멈추고, 바뀐 줄에는 형광펜 띠를 0.8초 뒤에 얹습니다
  - 참고 구현: HyperFrames의 `code-morph` 블록(Shiki Magic Move 방식을 시간축으로 다시 짠 것, Apache-2.0). 코드를 그대로 가져오면 저작권 표시가 필요하므로 방식만 참고해 직접 짜는 것을 권합니다
- **확인 여부**: HyperFrames 0.9.56을 npm으로 설치해 `code-morph` 블록을 1920×1080·7초로 렌더링해 봤습니다 — CPU만으로 **17초에 완성**, 프레임을 열어 코드가 for 반복문 → filter·map 한 줄로 바뀌는 과정을 확인했습니다. 우리 Playwright 방식으로 다시 짠 것은 아직 만들지 않았습니다
- **라이선스·비용**: HyperFrames Apache-2.0(무료), shiki MIT, shiki-magic-move MIT. 코드 글꼴은 Noto Sans Mono CJK(작업 공간에 있음, SIL OFL)를 쓰면 한글 주석도 깨지지 않습니다
- **출처**: [heygen-com/hyperframes](https://github.com/heygen-com/hyperframes), [npm hyperframes](https://www.npmjs.com/package/hyperframes), [npm shiki](https://www.npmjs.com/package/shiki), [npm shiki-magic-move](https://www.npmjs.com/package/shiki-magic-move)

### 2. 말하는 자리 형광 자막 — 자막 상자 안에서 지금 읽는 낱말까지 노란 띠가 차오름
- **무엇이 나아지나**: 지금 자막은 문장 하나를 통째로 보여 줍니다. 숏폼은 소리를 끄고 보거나 빨리 넘기는 사람이 많아, **지금 어디를 읽는지**가 보이면 눈이 자막을 따라가고 핵심 낱말에 머무릅니다. GUIDE 5장 '자막 상자를 껐다 켜지 않기'와 충돌하지 않습니다(상자는 그대로, 상자 안 글자 색만 바뀜)
- **어울리는 오픈소스**: 숏폼 전반, 특히 화면 그림이 단순해서 자막이 주인공인 장면(설명·비유 장면). 롱폼은 화면에 볼 것이 많아 산만할 수 있으므로 미리보기 정도에만 권합니다
- **도입 방법**: `caption()`에서 문장마다 이미 알고 있는 실제 음성 길이(`retime.py 길이.json`)를 쓰고, 문장 안에서는 **글자 수 비례**로 진행 위치를 계산해 낱말 뒤에 노란 띠를 왼쪽부터 칠합니다(띠가 지나간 글자는 검정). 낱말별 정확한 시각은 음성 인식(Whisper 등)이 필요하지만 모델 다운로드(Hugging Face)가 막혀 있어, 문장 단위 실제 길이 + 글자 비례로 어림합니다 — 한 문장(2~5초) 안의 어긋남이라 크지 않을 것으로 보이나, 운영자 음성으로 직접 맞춰 봐야 합니다
- **확인 여부**: 세로 1080×1920 캔버스에 Noto Sans CJK로 시범 자막을 그려 1.0초·2.6초 프레임을 열어 봤습니다 — 한글 낱말 단위 띠, 줄바꿈, 글자가 반쯤 칠해지는 경계까지 정상입니다. 실제 음성과 맞춘 확인은 아직 하지 않았습니다
- **라이선스·비용**: 직접 짜는 코드라 해당 없음. 비슷한 방식이 HyperFrames `caption-pill-karaoke`·`caption-highlight` 컴포넌트에 있으나(Apache-2.0) 방식만 참고했습니다
- **출처**: [heygen-com/hyperframes](https://github.com/heygen-com/hyperframes) (catalog의 caption 컴포넌트 목록)

## 지켜볼 것
- **HyperFrames 자체(HTML → 영상 렌더러, 별 약 8.5만, 2026-11-16에도 새 버전)**: 우리와 같은 'HTML을 프레임 단위로 찍어 mp4' 방식이고, 작업 공간에서 CPU로 렌더링됩니다(위 확인). 다만 지금 Playwright 파이프라인이 이미 잘 돌고, 음성 맞추기(`retime.py`)·깜빡임 방지 규칙이 우리 코드에 맞춰져 있어 **렌더러를 바꿀 이유는 없습니다.** 대신 `npx hyperframes catalog`의 블록 목록(차트 이야기 `chart-story`, 단계 칩 `state-chip-rail`, 전·후 와이프, 숫자 바퀴 등)을 새 연출을 찾을 때 **보는 견본집**으로 쓸 만합니다. 주의: 기본으로 사용 통계를 보냄(`hyperframes telemetry disable`로 끔), 일부 템플릿은 유료(Pro)
- **유튜브 쇼츠 '시즌·에피소드' 묶기**: 쇼츠를 시즌·에피소드로 묶는 기능이 2026년 11월 초 소식으로 정리돼 있습니다([SocialBee 정리](https://socialbee.com/blog/youtube-updates/), 원 발표 [Made on YouTube 2026](https://blog.youtube/news-and-events/innovation-youtube-era-made-on-viewers-creators/)). 매일 올리는 오픈소스 숏폼을 "오늘의 오픈소스 시즌 1"처럼 묶으면 이어 보기를 기대할 수 있습니다. 한국 계정·스튜디오에 메뉴가 열렸는지는 확인하지 못했으므로, 다음 업로드 때 운영자가 스튜디오에서 확인해 보시기 바랍니다
- **유튜브 AI 표시 규정**: 2026년 5월부터 실사처럼 보이는 AI 콘텐츠에 자동 표시가 붙기 시작했습니다. 애니메이션·인포그래픽·자동 자막은 표시 의무 대상이 아니고, 실제 인물을 흉내 낸 합성 음성은 대상입니다([정리 기사](https://kingy.ai/news/youtube-ai-labels-automatic-video-disclosure/)). 우리 영상(직접 그린 2D 화면 + 특정 인물을 흉내 내지 않는 음성)은 해당하지 않을 것으로 보이나, 정확한 기준은 유튜브 고객센터 '변경되거나 합성된 콘텐츠 공개' 도움말을 따르시기 바랍니다
