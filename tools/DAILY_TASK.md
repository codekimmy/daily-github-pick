# 매일 예약 작업 지시문

저장소 `codekimmy/daily-github-pick`에 오늘의 오픈소스 1개를 추가한다.

1. 저장소를 받아 `GUIDE.md`, `INDEX.md`, `templates/`, 가장 최근 날짜 폴더 하나를 읽고 형식과 문체를 그대로 따른다.
2. GitHub Trending(일간·주간)과 최근 별 급상승 저장소를 웹에서 찾아 후보 5개 이상을 모은다. `INDEX.md`에 이미 있는 저장소는 제외. GUIDE 1장 선정 기준대로 **1순위(일반인이 직접 써볼 수 있는 것)를 먼저** 고르고, 없을 때만 2순위(직접은 못 써도 신기하고 생활과 연결되는 것). 순수 개발자 도구는 제외. **작업 공간에서 실제 결과물을 만들 수 없는 후보(그래픽카드 필요, Hugging Face 모델·GitHub 릴리스 파일 필요, 실행이 막힘)는 제외**하고, 고르기 전에 설치·실행 가능성을 먼저 확인한다(GUIDE 1장). 인기 목록에 조건에 맞는 후보가 없으면 `CANDIDATES.md`의 예비 후보(⭐ 우선)에서 고른다. 연속 같은 분야는 피한다. GUIDE 6장 기준으로 일반인 쓸모 별점과 '이걸로 할 수 있는 것' 3줄을 모든 원고 맨 앞에 넣는다.
3. 별·포크·라이선스·언어·버전은 GitHub 페이지와 패키지 저장소에서 직접 확인한다.
4. 작업 공간에서 실제로 설치·실행한다. 결과 수치, 걸린 시간, 막힌 점을 기록한다. 실행이 막히면(하드웨어·유료 키·모델 다운로드 필요, 실행 거부 등) 그 후보를 버리고 2단계 후보 목록의 다음 프로젝트로 다시 시작한다. 결과물 없이 원고만 만들지 않는다. 가능하면 `demo/`에 작은 활용 예제를 직접 구현한다.
5. 녹화: 데모 스크립트를 `demo/demo.sh`로 만들고 `tools/record_terminal.sh`로 `media/terminal.gif` 생성. 결과가 웹 화면이면 `tools/record_page.py`로 `media/*.mp4` 생성, 그리고 GUIDE.md 5장에 따라 **과정이 보이는 45~60초 애니메이션**(장면마다 6초 이상, 다 나타난 뒤 2.5초 이상 멈춤 — GUIDE 5장 '내용을 파악할 시간')을 가로·세로 두 버전으로 만들고(`2026-10-29-graphify/demo/grow-animation/`의 프레임 렌더링 방식 참고), README용 GIF(640px, 10MB 이하)도 만든다. CDN 스크립트가 막히면 npm에서 받아 HTML에 인라인한다. 녹화 결과는 프레임을 직접 열어 빈 화면이 아닌지 확인한다.
5-1. **유의사항 문구(필수, GUIDE 6-1장)**: 롱폼 엔딩 카드와 과정 애니메이션(가로·세로) 엔딩에 작은 글씨로 "정보 제공용 · YYYY-MM-DD 클라우드 시연 결과(운영자 직접 검증 아님) · 주제별 핵심 경고"를 렌더링에 넣는다(예: `2026-10-31-zxcvbn/demo/anim/anim.html`의 sceneEnd, `demo/long/long.html`의 SC.end). 렌더링에 못 넣었거나 음성·배경음악을 입힌 버전을 따로 만들었다면 `tools/end_disclaimer.py`로 **모든 mp4**에 얹는다. GIF는 문구가 들어간 mp4로 만든다. 마지막 프레임을 직접 열어 문구가 보이고 다른 글자와 겹치지 않는지 확인한다.
6. `YYYY-MM-DD-이름/`에 README.md, blog.md, youtube-long.md, shorts.md를 templates 형식으로 작성한다. 초보자 눈높이 규칙(GUIDE 3장)을 반드시 지킨다. **문체는 합니다체(~합니다·~입니다·~됩니다)로 통일하고 해요체(~해요·~예요)는 원고·설명란·음성 대본·영상 자막·화면 글자 어디에도 쓰지 않는다(GUIDE 3장).** 명령어는 Windows cmd 기준. 원문 문장을 베끼지 않는다. **모든 원고·영상에 유의사항을 넣는다(GUIDE 6-1장). README·blog의 `## ⚠️ 유의사항` 절 맨 첫 줄에 `※ 이 글은 오픈소스 프로젝트를 소개하는 정보 제공용이며, 특정 프로그램 사용을 권하거나 결과를 보장하지 않습니다.`를 그대로 넣는다(제목 바로 아래 맨 위가 아님, 2026-11-10 운영자 요청).** **행위의 주체(누가)와 대상(무엇을)을 빼고 말을 줄이지 않는다(GUIDE 3장): 원고·자막·음성 대본·설명란 모두.** **모든 이미지에 대체 텍스트(alt)를 정리한다(GUIDE 5-2장): blog.md 맨 위 주석에 `파일명 → 문구` 목록 + 본문 `[이미지: 파일명 | 대체 텍스트: 문구]`, README는 `![문구](경로)`.** 운영자가 직접 써 보고 쓴 후기처럼 읽히는 문장(직접 써봤다·써본 후기·해봤더니·테스트했어요·후기·리뷰 등)은 원고·자막·대본·설명란 어디에도 절대 쓰지 않는다(GUIDE 3장). 커밋 전에 금지 표현을 검색해 0건인지 확인한다.
6-1. 롱폼·숏폼 영상 각각의 음성용 대본 `narration-long.txt`, `narration-shorts.txt`를 GUIDE 5-1장 규칙대로 만든다(구간 시간 + 영어·숫자를 한글 읽기로). **대본은 짧고 분명하게 쓰고, 문장 사이 쉼이 2초 이하가 되도록 `voice/retime.py`로 영상 시간을 음성 길이에 맞춘 뒤 렌더링한다(GUIDE 5-1, 2026-11-11 운영자 요청).**
6-2. 커밋 전 점검: 모든 이미지의 대체 텍스트(blog 주석 목록·본문 자리 표시·README `![문구]`)가 빠짐없이 있는지, README·blog의 `## ⚠️ 유의사항` 절과 그 절 맨 첫 줄 `※ 이 글은 …` 문장, youtube-long 설명란 맨 아래 `※ 유의사항` 3줄, youtube-long·shorts 설명란 맨 첫 줄 `※ 이 영상은 …` 문장, shorts 설명란 해시태그 앞 주제별 1줄, youtube-long 태그 맨 앞과 shorts 해시태그 첫 자리에 오픈소스 영문 이름(2026-11-12 운영자 요청), 모든 mp4 엔딩 유의사항 문구가 있는지 확인한다. 하나라도 없으면 커밋하지 않고 채운다.
7. `INDEX.md`에 한 줄 추가(예비 후보에서 골랐다면 `CANDIDATES.md` 해당 줄 추천 칸에 `✅ Day N` 표시) 후 main에 커밋·푸시. 커밋 메시지: `Day N: 저장소명 — 한 줄 설명`.
8. 마지막에 사용자에게 한국어로 짧게 보고(음성 대본을 보낼 때는 문장만 있는 `narration-long-text.txt`, `narration-shorts-text.txt`를 보낸다): 오늘의 프로젝트 한 줄 소개, 직접 해본 핵심 결과 1~2줄, 저장소 폴더 링크, 대표 GIF/영상 파일 전송.
