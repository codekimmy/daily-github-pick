## 3. 날짜 폴더에서 쓰는 순서
1. 지금처럼 `bench.py` → `results.json`, `mkdata.py` → `data.js`(RES, 필요하면 MAT), 대본 → `voice/retime.py` → `timing.js`(LONG, SHORTS)까지 만든다 (**바뀌지 않음**)
2. `tools/motion/page-template.html`을 `demo/render/page.html`로 복사하고 `endScene.name`(이름 · 한 줄 비유)을 고친다
3. `demo/render/scenes.js`를 만든다: 맨 위에 `const DISCLAIMER = [...]`(엔딩 유의사항 2줄), `const SCENES = {}`. 장 id마다 `SCENES.장id = S => { …만들기… return t => { …그리기… } }`
   - **안 만든 장은 기본 장면(fallback)으로 자동으로 그려진다** (장 제목 = 큰 제목, 자막 문장마다 카드 1장). 시간이 모자라면 미리보기·타이틀·핵심 시연 2~3장만 직접 만들고 나머지는 기본 장면으로 둬도 영상은 완성된다
   - 숏폼(SHORTS)의 장 id(`s_hook` 등)도 같은 방식. 세로·가로 둘 다 `S.V`(세로면 true)로 배치만 바꾼다
4. 확인 화면을 찍어 본다 (장마다 '다 나타난 순간' 1장 이상, 전환 순간 1장, 마지막 프레임)
   `python3 ../../../tools/motion/render_motion.py long chk --only 3,10,25,…,last`
   `python3 ../../../tools/motion/render_motion.py anim chk --only 2,10,…,last 1080 1920`
5. 렌더링
   - 롱폼: `python3 ../../../tools/motion/render_motion.py long ../../media/이름-long.mp4`
   - 숏폼 세로: `… anim ../../media/이름-anim-vertical.mp4 1080 1920` / 가로: `… anim ../../media/이름-anim.mp4 1920 1080`
   - 소요(CPU 2개 작업 공간): 롱폼 5분 ≈ 8~9분, 숏폼 45초 ≈ 1분 30초 (한 번에 끝나지 않으면 백그라운드로 돌리고 기다린다)
6. 음성·배경음악 입히기(`align.py` 등)·엔딩 문구 확인은 지금 방식 그대로

## 4. 장면 함수 기본 꼴
```js
SCENES.demo1 = S => {                       // S.cue(i) = 자막 i 시작 초, S.cueEnd(i), S.text(i), S.dur, S.V(세로?)
  const c0 = S.cue(0), c1 = S.cue(1);
  const caps = [M.caption(c0, c1 - .2, [['와이파이', 'QR은'], ['*정해진 형식*']]),   // *강조*
                M.caption(c1, null, [['*0.06초*', '만에', '완성']])];
  const tm = M.term(110, 380, 860, 300);                                           // 명령 창
  const qc = M.box(1150, 150, 640, 640);  const code = M.qr(MAT.wifi, 572, {left:'30px', top:'30px'}, qc);
  const st = M.stamp('0.06초', 1560, 120);
  return t => {                                                                    // t = 장 안의 초. 상태를 쌓지 말 것(시간의 함수만)
    caps.forEach(c => c.render(t));
    const a = M.popIn(t, c0 + .2);  M.tf(tm.el, 0, (1 - a) * 300, 1, 0, a > 0 ? 1 : 0);
    tm.render(t, [{ at: c0 + .6, text: 'segno "WIFI:…" -o wifi.png' }, { at: c0 + 3, kind: 'out', text: '✓ wifi.png 저장' }]);
    code.draw(t, { stamp: c1, dur: 1.8 });  st.render(t, c1 + 2.2);
  };
};
```
- **시간은 반드시 `S.cue(i) ± 초`로 잡는다.** 숫자를 그대로 쓰면 retime으로 자막 구간이 바뀔 때 화면과 음성이 어긋난다
- 장 끝에 '사라지는' 움직임을 넣지 않는다. 장이 바뀔 때 엔진이 앞 장의 마지막 모습을 겹쳐 바꾼다(빈 화면 방지)
- 숫자는 `RES`(시연 측정값)에서만 가져온다. 화면에 새 숫자를 지어 넣지 않는다

## 5. 연출 사전 — 대본 문장 종류 → 쓸 연출
| 대본이 말하는 것 | 연출 | 함수 |
|---|---|---|
| 장의 요점 (모든 장) | 큰 제목, 핵심 낱말 1개만 `*강조*` | `M.caption` |
| 명령 실행·설치 | 명령 창 타이핑 → 결과 줄 톡 | `M.term` |
| 걸린 시간·개수·크기 (숫자 1~2개) | 카운트업(1.5초 이상) + 도장 1개 | `M.count`, `M.stamp` |
| 결과 그림·파일이 생김 | 카드가 톡 떨어짐 + 내용이 만들어지는 과정 (QR이면 `M.qr` 찍히기) | `M.popIn`, `M.qr` |
| "읽어 보니/확인하니 그대로" | 읽는 띠가 지나감 → 결과 카드 줄마다 ✓ | `M.scanAt`, 카드 줄 |
| 설정·단계별 비교 | 카드 나란히 + 아래 ✓/✗ 알약 줄(같은 줄은 한꺼번에) + 이긴 것만 남기고 회색 | `M.pill`, `M.pillRender` |
| 주의·한계·실패 | 빨간 펜 동그라미 / 취소선 + 손글씨 한 마디 | `M.pen`, `M.circleAround`, `M.hand` |
| A → B 변화 | 휘어진 빨간 화살표 + 숫자 바뀜 | `M.arrowPath`, `M.count(from)` |
| 별점 | 별이 하나씩 채워짐 | `M.stars` |
| 쓰임새 3가지 | 아이콘 타일 카드 3장(0.8초 간격) | `M.iconTile`, `M.icon` |
| 그 밖의 문장 | 기본 장면 카드 | (자동) |

**한 장면에 강조(도장·펜·손글씨)는 합쳐 2개까지, 영상 전체 도장은 3~4개까지.** 모든 것이 튀면 아무것도 안 튄다.

## 7. 지켜야 할 규칙 (GUIDE와 같음 — 여기서 다시 확인)
- **화면 글자(큰 제목·손글씨·도장 포함)도 합니다체 또는 명사형**(~함·~됨·~읽힘·~나옴). 해요체·반말(`버텼다`, `됐어`) 금지
- 장면 사이 검은(빈) 화면 금지 → 엔진이 처리. 장면 안에서 모든 요소를 동시에 지우지 않는다
- 카드·목록이 하나씩 나타날 때 간격 0.8초 이상. 한 묶음(같은 줄의 알약, QR 4장 동시 낙하)은 0.12~0.22초 '잔물결' 간격으로 한꺼번에
- 숫자 카운터 1.5초 이상, 다 오른 뒤 2초 이상 보이기
- 다 나타난 뒤 2.5초 이상 멈춤(음성 속도가 우선인 경우는 GUIDE 5-1)
- 엔딩 유의사항 문구는 엔진이 넣음(`DISCLAIMER`). 마지막 프레임을 열어 겹치지 않는지 확인
- 보조 캐릭터는 **냥봇만** 쓴다 (2026-11-24 운영자 확정, 9장). 다른 캐릭터·참고 영상 캐릭터는 쓰지 않는다

## 8. 문제가 생기면
| 증상 | 원인·해결 |
|---|---|
| 장 전체가 카드 목록(기본 장면)으로 나옴 | `SCENES.장id`가 없거나 오류. `render_motion.py`가 '페이지 오류'를 찍어 줌 → 고침 |
| 빨간 펜 동그라미 자리가 어긋남 | `M.circleAround`는 **만들 때 자리** 기준. 요소를 움직이는(transform) 중이면 직접 `M.ellipsePath(x,y,rx,ry)`로 |
| 자막 상자 밖으로 글자가 나감 | 자막 문장이 너무 김 → 대본 쪽 자막 문구를 줄인다 |
| `p.chromium.launch()` 실패 | `render_motion.py`가 `/usr/bin/google-chrome`으로 자동 대체 |
| 렌더 시간이 10분 넘음 | 백그라운드로 실행하고 끝날 때까지 기다린다. `--jobs`는 CPU 수보다 크게 하지 않는다 |

## 9. 보조 캐릭터 냥봇 (2026-11-24 운영자 확정)
고양이 귀 바이저 로봇. **말하지 않고 반응만** 한다 (내레이션은 AI 목소리 그대로 — 캐릭터가 화자처럼 보이면 목소리와 안 어울린다는 2026-11-15 보류 사유를 피하는 방식). 눈은 크림색 타원(빛 번짐 없음, 운영자: 밝은 눈이 거슬림).

```js
const nb = M.buddy(1636, 548, .62);            // 롱폼·가로: 오른쪽 아래 (카드는 x 1620 안쪽에)
// 세로 숏폼: M.buddy(770, 168, .62) — 오른쪽 위, 큰 제목 옆 (큰 제목은 두 줄로 짧게)
const NB = [{ at: c0 + .8, a: 'enter' }, { at: c0 + 1.5, a: 'wave' }, { at: c1 + 2, a: 'point', dir: 'left' },
            { at: c2 + .5, a: 'oops' }, { at: c2 + 3, a: 'stamp' }, { at: c3 + 3.6, a: 'happy' }];
return t => { …; nb.render(t, NB); };
```
| 동작 `a` | 모습 | 쓰는 때 |
|---|---|---|
| `enter` / `leave` | 아래에서 톡 올라옴 / 내려감 | 장 첫 자막 직후 / 거의 안 씀(장 전환이 처리) |
| `wave` | 손 흔들기 + 웃는 눈 | 장 첫 등장 인사 (영상에 1~2번) |
| `point` (`dir: left·up·right`) | 팔로 가리키며 고개 돌림 | 화면에서 지금 볼 곳을 짚을 때 |
| `look` | 고개 갸웃 + ? | 질문형 자막("가리면?") |
| `nod` | 끄덕 + 웃는 눈 + 초록 ✓ | 성공·읽힘·완료 |
| `oops` | 펄쩍 + 동그란 눈 + 빨간 ! | 실패·오류·주의 |
| `stamp` | OK 도장을 들었다 쾅 (시작 0.35초 뒤 찍힘) | 화면 도장(`M.stamp`)과 같은 순간 — 도장 시각 −0.35초에 시작 |
| `pen` | 빨간 펜으로 그리는 손짓 | 빨간 펜 동그라미가 그려질 때 |
| `happy` | 웃는 눈으로 통통 | 장 마지막 정리 |
동작이 없을 땐 숨쉬기·깜빡임·꼬리 흔들기를 저절로 한다.

**규칙**
- 배치 자리를 먼저 비운다: 롱폼·가로는 **오른쪽 280px**(카드가 x 1620을 넘지 않게), 세로는 **오른쪽 위 300×300**(큰 제목 두 줄, 한 줄 9자 안팎)
- 반응은 **장면마다 2~4번**, 자막·화면 사건과 같은 순간에만. 계속 움직이면 화면 내용보다 눈에 띈다
- 나오는 장: 롱폼은 미리보기·타이틀·시연 장들·정리(설치·옵션처럼 글이 많은 장은 빼도 됨), 숏폼은 모든 장면. 엔딩 카드에는 넣지 않는다
- 말풍선 글자를 넣지 않는다 (✓ ! ? 표시만). 대사처럼 보이면 AI 목소리와 부딪힘
- `flip` 옵션은 쓰지 않는다 (도장 글자가 뒤집힘)
